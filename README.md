# RNBO_RP2350_Bridge

RNBO_RP2350_Bridge is a bare-metal C++ project designed to bridge Cycling '74 Max/RNBO audio patches with a **Raspberry Pi Pico 2 (RP2350)** via full-duplex I2S, enabling real-time hardware audio DSP (such as guitar effects) on a microcontroller.

Based on [Cycling '74 rnbo.example.baremetal](https://github.com/Cycling74/rnbo.example.baremetal).

> **Note / Prerequisite**: This project assumes that your RNBO patch is designed purely for real-time audio signal processing using **`gen~`** inside RNBO (with a fixed audio vector size and sample rate).

---

## Key Features

- **Real-Time `gen~` DSP on RP2350**:
  - Runs C++ code exported via **RNBO Minimal Export** directly on the RP2350's ARM Cortex-M33 single-precision hardware FPU (`RNBO_USE_FLOAT32`).
  - Zero dynamic memory allocations during the real-time audio loop using a pre-allocated **TLSF** memory pool and ping-pong DMA buffers.

- **Full-Duplex 32-bit I2S Audio Engine (PIO + DMA)**:
  - **ADC Input (PCM1808)** and **DAC Output (PCM5102A)** run simultaneously in lockstep using three synchronized PIO state machines (`256fs` MCLK + `64fs` BCK + `1fs` LRCK) and dual DMA channels.
  - Automatic mono-to-stereo input routing (`L + R` summing) so a mono (TS) guitar cable plugged into a stereo (TRS) input jack drives both stereo channels of the RNBO effect.

- **Noise-Free Analog Gain Control**:
  - Two hardware potentiometers control **Input Gain** (`GP27 / ADC1`) and **Output Gain** (`GP26 / ADC0`).
  - Combines 8x oversampling, a minimum deadzone, hysteresis (`±12` LSB), and per-sample 1st-order low-pass smoothing to eliminate zipper noise.

## System Architecture

### Hardware (Raspberry Pi Pico 2 + I2S Audio Codec)
- **Microcontroller**: Raspberry Pi Pico 2 (RP2350, ARM Cortex-M33 @ 150 MHz, 520 KB SRAM)
- **ADC (Audio Input)**: PCM1808 (24-bit I2S Slave Mode; `FMT` = GND, `MD0` = GND, `MD1` = GND, `5V/VCC` = VBUS 5V, `3.3V/VDD` = 3.3V)
- **DAC (Audio Output)**: PCM5102A (32-bit I2S; `SCK` = GND, `FLT` = Low, `DEMP` = Low, `FMT` = Low, `XSMT` = High 3.3V)
- **Pin Assignments**:
  - **I2S Shared Clocks**: `BCK` = GP10, `LRCK (LCK)` = GP11
  - **I2S DAC Data Out (Pico 2 → PCM5102A)**: `DIN` = GP12
  - **I2S ADC Data In (PCM1808 → Pico 2)**: `DOUT` = GP9
  - **I2S Master Clock (Pico 2 → PCM1808)**: `SCK (MCLK, 256fs)` = GP21
  - **Potentiometers (ADC)**: Output Gain = GP26 (`ADC0`), Input Gain = GP27 (`ADC1`)

### Software (RNBO Minimal Export + Pico SDK)
- **DSP Engine**: Cycling '74 RNBO Minimal Export (`export/rnbo_source.cpp.h`) using `gen~`
- **Sample Rate / Vector Size**: `44100 Hz` / `64 samples` (fixed block size)
- **Memory Management**: Two-Level Segregated Fit (`tlsf`) allocator backed by a 256 KB pool allocated from SRAM

## Required Modifications from the Original RNBO Bare-Metal Example

To port the original desktop offline demo ([`Cycling74/rnbo.example.baremetal`](https://github.com/Cycling74/rnbo.example.baremetal)) to run in real time on the **Raspberry Pi Pico 2 (RP2350) + PCM1808 + PCM5102A**, the following modifications are required:

| Item | Original `main.cpp` | Pico 2 (`RNBO_RP2350_Bridge`) | Reason |
| :--- | :--- | :--- | :--- |
| **Floating-Point Precision** | `//#define RNBO_USE_FLOAT32` (64-bit `double` by default) | Enable `#define RNBO_USE_FLOAT32` and add `-fsingle-precision-constant` in `CMakeLists.txt` | The RP2350 (Cortex-M33) hardware FPU only accelerates **32-bit `float`**. Using 64-bit `double` falls back to slow software emulation and doubles delay buffer RAM usage. |
| **Included RNBO Source File** | `#include "export/rnbo_source.h"` | `#include "export/rnbo_source.cpp.h"` | Matches the C++ source file name generated by RNBO Minimal Export. |
| **TLSF Memory Pool Size (`poolSize`)** | `const size_t poolSize = 100 * 1024 * 1024;` (100 MB) | `const size_t poolSize = 256 * 1024;` (256 KB) | RP2350 has **520 KB** of internal SRAM in total; a 100 MB allocation fails immediately (`NULL`). Allocating 256 KB via `::malloc(poolSize)` properly advances Newlib's `_sbrk` heap pointer so it never collides with C++ `operator new` or `std::vector`. |
| **RNBO Instance Storage** | Local stack variable inside `main()`: `RNBO::rnbomatic<MyEngine> rnbo;` | Global `static` variable: `static RNBO::rnbomatic<MyEngine> rnbo;` | The `rnbomatic` object (including internal signal buffers and event queues) is several kilobytes in size and would cause a **stack overflow** if placed on the microcontroller's small stack. |
| **Delay Buffer Type & Size (`rnbo_source.cpp.h`)** | `this->sr` (65,536 samples) × 12 buffers (`Float64Buffer` = ~6 MB) | `4096` samples × 12 buffers (`Float32Buffer` = 192 KB) | Reduces delay line memory footprint so all 12 delay buffers in `gen~` fit comfortably within the 256 KB TLSF pool on RP2350. |
| **Audio I/O Loop** | Offline loop (`for (int i = 0; i < SAMPLERATE/VECTORSIZE; i++)`) writing to `AudioFile` | Infinite `while (true)` loop synchronized to **PIO + DMA Full-Duplex I2S** transfers every 64 samples | A hardware audio effect must continuously process incoming ADC samples and output DAC samples in real time. |
| **Sample Format Conversion (`int32_t` ⇔ `float`)** | None (`AudioFile` handles format conversion on desktop) | Normalize incoming 32-bit I2S integers (`int32_t`) to `float (-1.0f..+1.0f)`, and convert processed `float` samples back via `float_to_int32()` | RNBO performs DSP in normalized `float`, whereas the physical I2S wire protocol for PCM1808 and PCM5102A transmits 24-bit/32-bit two's complement signed integers. |
| **Hardware Gain Control (ADC)** | None | Read `GP27 (ADC1)` for Input Gain and `GP26 (ADC0)` for Output Gain via `update_pot_target_gain()` + per-sample smoothing | Provides physical knob control over input and output levels without potentiometer jitter noise. |

## Getting Started

### Prerequisites
- **[Raspberry Pi Pico SDK](https://github.com/raspberrypi/pico-sdk)** (v2.0.0 or later with RP2350 / `pico2` support) installed on your machine (or via the official Raspberry Pi Pico VS Code extension).
- **CMake** (v3.17+).
- **Cycling '74 Max / RNBO** to export your own `gen~` patch.

### 1. Export Your RNBO Patch
1. Build your real-time audio effect using `gen~` inside a RNBO patch (`~rnbo`).
   - Make sure delay buffers inside `gen~` are sized appropriately for the RP2350's 520 KB SRAM (e.g., `4096` samples per delay line, using `Float32Buffer`).
2. Export the C++ source code into the `export/` directory at the root of this repository (`export/rnbo_source.cpp.h` and `export/common/`).
   - Ensure the export settings use a fixed vector size of **`64`** and sample rate of **`44100`**.

### 2. Build the Firmware
```bash
git clone https://github.com/yuki-sato-0402/RNBO_RP2350_Bridge.git
cd RNBO_RP2350_Bridge
mkdir build && cd build
cmake -DPICO_BOARD=pico2 ..
cmake --build .
```

### 3. Flash to Raspberry Pi Pico 2
1. Hold down the **BOOTSEL** button on the Raspberry Pi Pico 2 while connecting it to your PC via USB.
2. Copy the generated `build/baremetal.uf2` file to the mounted **`RP2350`** drive.
